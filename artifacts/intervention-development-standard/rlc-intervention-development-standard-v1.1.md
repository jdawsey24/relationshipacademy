## 1. Barrier ≠ Competency ≠ Change Target (governing distinction — reinforced)
> - A **Developmental Barrier** identifies *what may interfere* with developmental functioning
>   (canonical categories: Internal / Relational / Environmental).
> - A **Developmental Competency** identifies *a developmental capacity* (canonical `kb_competencies`).
> - A **Change Target** identifies *what an intervention is attempting to change*.
> **These are not interchangeable.** Classifying an Observed Interference Pattern under a barrier category does
> **not** establish that the competency architecture contains the full capacity required to move the Change
> Target; naming contributing competencies does **not** establish complete coverage of the target.

**Operational consequence (new gate in the Evidence Chain):** when a Change Target's required capacity is
**not demonstrably covered** by one or more canonical competencies (even if contributing competencies exist
and the interference maps to a barrier category), the intervention developer must raise a **Framework Coverage
Question (FCQ)** for human adjudication — **never** invent a competency or barrier, and **never** treat barrier
classification as coverage.

## 2. What counts as an RLC Intervention (unchanged — sound)
Retained from Draft v1 §1.1: an RLC Intervention is an intentional, specified change process acting on a
defined **Change Target**, through a stated **Change Mechanism**, in service of improved **Developmental
Application**, with specified user action, expected proximal change, and indications/contraindications/stop/
referral. It is distinct from education, recognition/validation, reflection/journaling, a delivery format
(worksheet/guide/challenge/lesson/video/scenario), a behavioral suggestion, a Practice, an Enhancement, a
clinical technique, and a Play. **Not every worksheet/exercise/prompt qualifies.** (Seven necessary conditions
retained verbatim.)

## 3. The Intervention Evidence Chain (unchanged, + the FCQ gate from §1)
```
Presenting Experience / Problem Expression → Functional Interference (established | conditional; evidence)
  → Developmental Context (Phase→Task) → Change Target
  → Relevant Competency and/or Canonical Barrier category   ⟵ if capacity not demonstrably covered ⇒ raise FCQ
  → Change Mechanism → Intervention Technique (+ source & evidence labels) → User Action
  → Expected Proximal Change → Developmental Application (BI-mapped) → Expected Developmental Outcome
  → Maintenance / Generalization
```
Governing question retained: *Why should doing THIS produce change in THIS target for THIS developmental
purpose?* No admission without an explicit answer, and no admission of a target with an **unresolved FCQ**.

## 4. Change-Mechanism requirement (unchanged — sound)
No closed mechanism taxonomy. Every intervention states: (1) user action; (2) the active process; (3) the
target it affects; (4) why that improves Developmental Application; (5) the observable proximal change.
Enforced: **mechanism ≠ technique ≠ delivery format ≠ content ≠ outcome.** "Worksheet" is not a mechanism;
"practice authenticity" is not a sufficiently specified intervention.

## 5. Evidence-strength labels — DUAL SYSTEM (APPROVED, retained)
Two independent labels per intervention, never collapsed:
- **External Technique Evidence:** `Empirically-Supported · Evidence-Informed · Not-Externally-Sourced`.
- **RLC Application Evidence:** `RLC-Theory-Derived · RLC-Pilot-Tested · RLC-Empirically-Supported`.
> **Governing principle (approved):** *evidence supporting an external technique does not establish empirical
> support for its application within the RLC Framework.* Every intervention must make explicit: (1) what is
> externally supported; (2) what has been adapted; (3) what is RLC theory-derived; (4) what has actually been
> tested within RLC. The current 333 = `Not-Externally-Sourced / RLC-Theory-Derived`.

## 6. Recognition/Context vs Intervention; interpretive targets without medicalizing (unchanged — sound)
Recognition/Context (normalization, validation, psychoeducation, literature, reframes that are not a change
technique) is allowed and often essential but **labeled accurately, not inflated into intervention** — except
where correcting a knowledge deficit **is** the mechanism (then it must meet all intervention conditions).
Interpretive/attentional/expectancy/decision/self-evaluation targets are supported **without assuming
pathology** and **without silently creating competencies/barriers**; where the target exceeds canonical
coverage, **raise an FCQ** (§1).

## 7. Intervention Evidence Hierarchy — Borrow → Adapt → Refine → Invent (APPROVED, retained)
| Level | Source | Use when |
|---|---|---|
| **L1 — Adopt** existing empirically-supported technique | external evidence base | an established technique already fits the target/mechanism (attribution + minimal change) |
| **L2 — Adapt** (evidence-informed) | external technique re-anchored to RLC | it can be responsibly adapted to the RLC target/context |
| **L3 — Refine** an existing RLC asset | the 333 / Enhancements | an existing RLC structure is sound but competency-general and needs target-specific content |
| **L4 — Invent** (theory-derived) | RLC theory | no sufficiently-fitting external/existing asset exists |
**Rules (approved):** the **RLC framework determines the developmental target and purpose**; established
intervention science is used whenever an adequate mechanism/technique exists; **new creation is the last
option, not the default**; **never select a modality first and force the problem into it** — the technique
fits the target. Ascend to L4 only after documenting why L1–L3 fail.

## 8. Consumer / Professional Suitability Standard (REVISED)
**Two revisions:** (a) suitability screening is **intervention-specific and may be collected at the point of
intervention selection/delivery** — the Snapshot is **not** expanded into a broad clinical severity/impairment
assessment; (b) **"professional" ≠ "clinical"** — facilitated/supported delivery is distinguished from
clinician-dependent delivery.

> **Snapshot vs Suitability Gate (principle).** The Snapshot / RLC assessment identifies the relational-
> developmental *pattern* and *developmental context*. The **intervention suitability gate** determines whether
> a *specific* intervention is appropriate for a *particular person in a particular context and delivery
> setting.* **Different interventions require different suitability information.** A low-risk evidence-
> observation intervention may need minimal screening; a psychologically activating intervention (self-
> evaluation, trauma-adjacent material, relational safety, coercion, substantial distress) may need a more
> robust, **intervention-specific** gate collected at selection/delivery. *(The screen itself is not designed
> here — methodological requirement only.)*

**Routing architecture (person × intervention × context; NOT mild/moderate/severe):**
| Outcome | Meaning |
|---|---|
| **R1 — Self-Guided** | appropriate for independent consumer use |
| **R2 — Supported / Facilitated** | benefits from structured facilitation, education, feedback, or guided implementation (Academy, workshop, RLC-trained facilitator, coach/educator) — **does not inherently require clinical treatment** |
| **R3 — Clinician-Dependent** | requires individualized clinical formulation, clinical judgment, psychological treatment skill, or management of meaningful psychological activation/risk |
| **Excluded / Safety Referral** | must not be delivered as an RLC developmental intervention in the present context (safety, coercion/abuse, acute destabilization, or a condition requiring different care/assessment) |
**Routing factors** (assessed on the intervention × context): technique complexity · misapplication likelihood
· emotional-activation potential · relational safety / coercion-abuse · clinical dependency · need for
individualized formulation · potential to worsen risk · need for real-time feedback · cognitive load · self-
correction ability · contraindications · result-interpretation ambiguity. Each intervention records its
**default routing outcome + the routing information it requires** (collected at selection/delivery).

## 9. Safety, Contraindications, Stop & Referral (unchanged — sound)
Every intervention specifies **Indications · Context Conditions · Contraindications · Stop Conditions ·
Referral/Escalation Conditions**, and passes the Change System **Context-Validity Rule**: no further evidence-
gathering where danger is established; no vulnerability/disclosure where unsafe; **do not challenge accurate
negative expectancy**; do not treat normal emotion as pathology; do not assume relationship preservation is
the goal. The Playbook is not turned into a diagnostic instrument.

## 10. Dosage · Feedback · Practice-vs-Intervention · Real-world Application · Cultural validity (unchanged — sound)
Retained from Draft v1: dosage is **mechanism-derived** (no arbitrary "30 days"; Provisional-labeled where
evidence is absent); feedback is **corrective-learning**, non-gamified; Enhancements/Practices reinforce
already-identified capacities and may be *components* of interventions but are not interventions when
interference blocks the capacity; every change-producing intervention specifies a **real-world transfer path**
(Learn → Rehearse → Apply → Observe → Adjust → Generalize) as the bridge to Developmental Application; cultural/
contextual assumptions are documented and healthy functioning is **not** defined as one cultural norm.

## 11. Success / Mastery Standard (PRESERVED)
> **Success = reduced Functional Interference + stronger Developmental Application** — expressed as increased
> capacity, better evidence discrimination, increased behavioral flexibility, appropriate decision-making,
> maintenance/generalization, and **recurrence tolerance**. **Never** defined as: never feeling it again ·
> eliminating unwanted thoughts · getting chosen · finding a partner · preventing rejection · keeping a
> relationship together · changing another person · eliminating conflict · a particular external outcome. The
> person may still experience the original thought/feeling/disappointment while functioning substantially
> better.

## 12. Versioning / validation lifecycle + Human review (unchanged — sound)
Lifecycle: `Proposed → Theory-Reviewed → Evidence-Reviewed → Usability/Pilot-Ready → Pilot-Tested → Revised →
Validation-Candidate → RLC-Empirically-Supported`; no intervention presented above its validated stage.
**Mandatory human adjudication** for: novel Change Targets · weak/ambiguous competency mappings · novel
mechanisms · clinical-technique adaptations · safety-sensitive interventions · professional/clinical routing ·
**Framework Coverage Questions** · weak-evidence interventions · psychologically-complex targets · culturally-
sensitive assumptions. **No automated pipeline may create a competency/barrier, raise the validated stage, or
resolve an FCQ.**

## DELIVERABLE — Intervention Portfolio Sufficiency Standard (NEW)
A **second-level** evaluation: individual-intervention validity (the Rubric) does **not** guarantee the
*portfolio* adequately addresses the Experience Cluster. This test runs **after** candidate interventions are
developed/admitted and **before** final Playbook translation.

**Trace:** `Experience Cluster → Problem Expressions → Functional Interference pathways → Change Targets →
Required Change Mechanisms → Admitted Interventions → Coverage → Remaining Gaps.`

**The test must consider:** coverage of major Problem Expressions · coverage of developmentally-relevant
Functional Interference pathways · whether each major Change Target has an adequate mechanism · unnecessary
duplication · whether multiple interventions are merely different **formats for the same mechanism** ·
Recognition/Context areas that appropriately need no intervention · **unresolved FCQs** · safety/routing
limits that prevent adequate delivery · whether the portfolio **collectively** provides a credible pathway
toward reduced Functional Interference and stronger Developmental Application.

**Not required:** an intervention for every statement or every Problem Expression. Some experiences
appropriately receive Recognition/Context, normalization, education, no intervention, professional referral,
or remain outside the developmental target. **The goal is functional sufficiency, not maximal coverage.**

**Portfolio disposition (+ required evidence):**
| Disposition | Assigned when… | Evidence required |
|---|---|---|
| **Sufficient** | every *major* interference pathway with an established Change Target has an adequately-mechanized admitted intervention; no unresolved FCQ on a major pathway | the completed trace table with each major target → admitted mechanism → coverage = adequate |
| **Sufficient with Recognition/Context Areas** | as above, **and** some expressions are appropriately Recognition/Context / referral (documented as intentional, not gaps) | the trace **plus** an explicit list of Recognition/Context/referral areas with rationale |
| **Partially Sufficient** | one or more *major* pathways lack an adequate intervention, carry an unresolved FCQ, or are undeliverable due to routing/safety limits | the trace identifying each uncovered major pathway + reason |
| **Insufficient** | major portions of the presenting problem have no credible pathway; the portfolio does not plausibly reduce Functional Interference | the trace showing majority-uncovered major pathways |
**Rule:** a portfolio dominated by **format-duplicates of one mechanism** cannot be rated Sufficient regardless
of intervention count.

## DELIVERABLE — Product-Claim Scoping Principle (NEW; not consumer copy)
> **The scope of a Playbook's promise must not exceed the demonstrated scope of its intervention portfolio.**
A Playbook must not imply it comprehensively addresses an Experience Cluster when the portfolio is only
**Partially Sufficient**. If admitted interventions address (e.g.) evidence discrimination and behavioral
application but not a major *interpretive* interference pathway (or that pathway carries an unresolved FCQ),
the product **must not** imply that following the Playbook fully resolves the presenting problem. Portfolio
disposition **bounds** the claim: *Sufficient* → may claim to help across the cluster's addressed pathways;
*Sufficient-with-Recognition* → claim + explicit "some aspects are supported through understanding/referral";
*Partially Sufficient* → claim only the specific addressed pathways. **Methodological/product-integrity
requirement — no consumer copy written here.**
