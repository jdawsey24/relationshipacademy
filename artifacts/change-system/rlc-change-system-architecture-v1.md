# Relationship Life Cycle™ Change System Architecture — Draft v1

**Status:** ARCHITECTURE / METHODOLOGY draft for human review. **Not** an intervention-generation task.
No new interventions, practices, competencies, barriers, clusters, tasks, domains, or phases were created;
the canonical framework is unmodified. Where a Change System concept could conflict with canon, the conflict
is flagged, not resolved by altering canon.

**Canonical grounding (verified in the live knowledge base + manuals cited therein):**
- 6 Phases → Developmental Tasks: Exploration→**Discernment**, Exclusivity→**Intentional Investment**,
  Expansion→**Integration**, Expiration→**Acceptance**, Recovery→**Healing**, Renewal→**Reengagement**
  (`fw_phases`).
- Per-competency canonical profile (`kb_competencies.detail`, *Operational Definitions Manual Ch.6,
  Construct 6.4*) supplies: **Developmental Competency**, **Behavioral Indicators / Incomplete Indicators**
  (the Behavioral Codebook: `fw_behavioral_indicators` + `studio_behavioral_indicators` +
  `studio_incomplete_indicators`, 3+3 per competency), **Common Developmental Barriers** (Internal /
  Relational / Environmental), **Common Developmental Enhancements**, **Developmental Application**,
  **Task Mastery**, **Transition Readiness**, **Developmental Functioning**, **Developmental Incongruence**,
  **Structural Context**, and the learning stages **Awareness → Practice → Application → Mastery**.
- Intervention/Practice library: 333 interventions + 333 practices, uniform templates per competency, all
  Pathway A (competency strengthening), Theory-Derived / In Development (prior two analyses).

**One-line thesis:** The Change System is an **operational/application architecture assembled entirely from
existing RLC constructs** — it adds *no new theory*. It contributes exactly two operational instruments (a
**Functional Interference Gate** and an explicit **Mechanism-vs-Format** distinction) and one *analysis-time*
scaffold (**Problem Expression**). Everything else is a reuse of canon.

## 1. Purpose and Scope
Translate a *presenting relational problem* into an *appropriate developmental change pathway*, answering:
**what needs to change · what interferes with it · which mechanism fits · how it's facilitated · how we know
developmental functioning improved** — without medicalizing normal relational emotion, without inventing
theory, and portably across Playbook / Academy / clinical / Institute use.

**In scope:** the logic connecting Experience Cluster → developmental change → measurement.
**Out of scope (this draft):** writing interventions, rewriting the 333 templates, the external literature
review, the full Intervention Development Standard, cross-cluster operationalization, UI.

## 2. Relationship to Canonical RLC Theory (answers §XX)
**Determination: Type B — an operational/application architecture, not a new theoretical component.** Tested
and confirmed. The developmental theory (Phase → Task → Competency → Application → Task Mastery, plus the
Developmental Influence System of Barriers/Enhancements) is untouched and does all the explanatory work. The
Change System is the *procedure* for applying that theory to a presenting problem.
- **Reused canonical constructs (no change):** Experience Cluster, Developmental Task, Competency, Behavioral
  Indicator, Developmental Barrier (Internal/Relational/Environmental), Developmental Enhancement, Practice,
  Developmental Application, Task Mastery, Transition Readiness, Developmental Functioning, Structural Context,
  Awareness→Practice→Application→Mastery.
- **Operational instruments introduced (non-theoretical, flagged):** (a) **Functional Interference Gate** —
  an *operationalization* of the canonical barrier inclusion criterion, generalized to gate all
  intervention; (b) **Change Mechanism vs Delivery Format** distinction — an operational discipline, not a
  new construct; (c) **Problem Expression** — an *analysis-time* scaffold, explicitly non-canonical and
  discardable. **§XXIII flags (b) as the one item closest to a theoretical addition; recommend it stay
  operational.**

## 3. Governing Principles
1. **Framework-first.** Every layer traces to a canonical construct or is declared operational-only.
2. **Presence ≠ interference.** A problem/emotion counts only when it interferes with the current task's
   capacities (the Gate).
3. **Cluster ≠ mechanism.** An Experience Cluster is a presenting problem, never a diagnosis, cause, barrier,
   or competency deficit by itself.
4. **Statement ≠ mechanism.** A Snapshot statement informs *hypotheses*; it never establishes an underlying
   cause.
5. **Mechanism ≠ format.** The active ingredient is distinct from the worksheet/guide/challenge that carries it.
6. **Parsimony.** Add an operational construct only if an existing canonical construct cannot perform the
   function.
7. **Non-pathologizing & safety-gated.** Normal emotion is preserved; intervention is bounded by indication,
   contraindication, and consumer/clinical fit.

## 4. Change System Model (the pipeline)

```
 ① PRESENTING EXPERIENCE      Experience Cluster (canonical) — a problem, not a mechanism
        │
 ② PROBLEM EXPRESSION         analytical grouping of related statements  [NON-CANONICAL, discardable]
        │
 ③ DEVELOPMENTAL CONTEXT      Phase → Developmental Task (the destination)   [canonical]
        │
 ╔══════▼═══════════════════════════════════════════════════════════════╗
 ║  ⟐ FUNCTIONAL INTERFERENCE GATE                                        ║
 ║  Does this expression interfere with acquisition / application /       ║
 ║  integration / maintenance of the capacities the current Task needs?   ║
 ║      NO ──────────────►  ⓔ RECOGNITION / CONTEXT  (validate; no        ║
 ║                              intervention; exit the pipeline)          ║
 ╚══════▼═════════════════════════════════════════════════ YES ══════════╝
        │
 ④ INTERFERENCE ANALYSIS      Competency-dominant │ Barrier-dominant │ Combined │ (Neither→ⓔ)  [canonical layers]
        │
 ⑤ CHANGE TARGET              what must change, traced to a Competency and/or a Barrier
        │
 ⑥ CHANGE MECHANISM           the active ingredient (the process expected to produce the change)
        │
 ⑦ INTERVENTION               Mechanism × Delivery Format × Indications/Contraindications × Intensity-tier
        │                        └─ SAFETY & CONSUMER/CLINICAL GATE (may block or refer)
 ⑧ DEVELOPMENTAL APPLICATION  enacted in authentic relational context  [canonical]
        │
 ⑨ OUTCOME · MAINTENANCE      reduced interference + stronger Task application; generalization  [Task Mastery / Transition Readiness]

   ══ MEASUREMENT SPINE (runs alongside ⑤–⑨): Target → Proximal → Application → Developmental → Maintenance indicators ══
```

**How this simplifies the proposed 12-step sequence (§II test):**
- **Moved** "Developmental Context" *earlier* (③, before the Gate): you cannot judge interference without
  knowing which Task's capacities are at stake.
- **Elevated** "Functional Interference" from a step to a **Gate** with an explicit no-intervention exit —
  this is the system's central non-pathologizing control.
- **Merged** "Barrier/Competency/Both/Neither" with the interference analysis (④); "Neither" routes to the
  same Recognition exit as a failed Gate.
- **Kept** Change Target (⑤) and Change Mechanism (⑥) distinct from Intervention (⑦) — the audit's key fix.
- **Made Measurement a spine**, not a terminal step, so indicators are specified with the target, not after.
- Net: **12 proposed nodes → 9 pipeline layers + 1 gate + 1 measurement spine**, no loss of function.

| Layer | Canonical? | Function | Must NOT |
|---|---|---|---|
| ① Presenting Experience | Canonical (Experience Cluster) | Entry; names the felt problem | be read as cause/diagnosis/target |
| ② Problem Expression | **No — analytical** | Group statements into hypothesis-forming presentations | become a cluster/barrier/competency/permanent taxonomy |
| ③ Developmental Context | Canonical (Phase/Task) | Set the developmental destination | be inferred from a single statement |
| ⟐ Interference Gate | Operational (from barrier criterion) | Decide if intervention is warranted at all | pathologize mere presence of emotion |
| ④ Interference Analysis | Canonical layers | Classify Competency/Barrier/Combined/Neither | assume a barrier without interference evidence |
| ⑤ Change Target | Reuses canon | State what must change, traced to a construct | float free of a competency/barrier |
| ⑥ Change Mechanism | Operational distinction | Name the active ingredient | be confused with delivery format |
| ⑦ Intervention | Reuses Enhancement/Practice | Mechanism made deliverable + safety/intensity | be evaluated by title/format |
| ⑧ Developmental Application | Canonical | Enact in real relational context | be equated with completing an exercise |
| ⑨ Outcome/Maintenance | Canonical (Task Mastery) | Reduced interference + generalization | require emotion elimination or an external outcome |

## 6. Experience Cluster Entry Logic (answers §III)
An Experience Cluster enters the system **only as a presenting problem** — a phenomenological starting point,
formally **not** a diagnosis, mechanism, barrier, competency deficit, cause, target, or developmental
construct. Its statement bank (~1,085 statements; the brief cites 1,069 — **reconcile, §XXIV**) supplies
*granular phenomenology* that may inform hypotheses about expression, interference, context, possible
barriers, possible competencies, and pathway. **A statement may support a hypothesis; it may never
establish a mechanism.** Formal rule:

> **Statement Evidence Rule.** A Snapshot statement is admissible only as *manifest self-report* about how a
> problem is experienced. Inferring a cause, barrier, competency deficit, attachment style, trait, or
> unconscious motive from a statement is prohibited. Mechanism claims require the Interference Gate (⟐) plus
> Interference Analysis (④), never a statement alone.

## 7. Problem Expression Rules (answers §IV — *actively tested for necessity*)
**Is the layer necessary? — Qualified YES, as analysis-time scaffolding only.** Break-test: could we run
the pipeline directly on (a) the whole Cluster or (b) individual statements? (a) loses the cluster's
heterogeneity (Cluster 1's self-worth core vs its evidence-reading periphery need different pathways);
(b) drowns in 101 units and tempts per-statement mechanism claims. Problem Expressions are the **minimum
grouping that preserves heterogeneity without proliferating taxonomy.** They earn their place *only* as a
bridge from phenomenology to hypothesis.

**Rules:**
1. **Function:** a parsimonious grouping of phenomenologically related statements within *one* Cluster that
   surfaces distinct *presentations* for pathway analysis. Hypothesis-forming, not classificatory.
2. **Status: analytical / transient, NEVER canonical.** Not stored as framework taxonomy; regenerated per
   analysis; may be revised or discarded. (Cluster 1's eight PEs are a *worked analysis*, not a canon.)
3. **Derivation:** derived from the statements' manifest content; must **partition** the Cluster's
   statements (every statement accounted for, once); labels are descriptive, not construct names.
4. **Anti-proliferation:** consolidate any two expressions describing the same presentation; cap at the
   smallest set that preserves distinct pathways; an expression that does not change the pathway is merged.
   No 1:1 forcing to barriers/competencies.
5. **Multiplicity:** **one person may present with several expressions simultaneously** (and typically does).
   Expressions are presentations of a problem, not mutually exclusive bins for people.
6. **Generalization:** the rules are cluster-agnostic; Cluster 1 is the prototype, not a special case.

## 8. Functional Interference Standard (answers §V — the central control)
**Distinguish problem *presence* from *functional interference*.** Presence of rejection, loneliness,
uncertainty, sadness, fear, disappointment, conflict, or grief is **not** dysfunction.

> **Interference Standard (refined from the canonical barrier criterion).** A condition warrants intervention
> only when it **meaningfully interferes with the acquisition, application, integration, or maintenance of
> the Developmental Competencies required by the person's current Developmental Task.** Distress, an unwanted
> outcome, or an unmet desire is *not*, by itself, interference.

**Evidence sufficient to move from "experiences X" → "X interferes":** at least one of —
- (i) the condition **distorts** the evidence/behavior a Task capacity depends on (e.g., pre-discounts
  positive relational evidence → interferes with Objectivity/Curiosity);
- (ii) the condition **prevents enactment** of an otherwise-available competency (e.g., fear blocks
  Authenticity that the person can articulate);
- (iii) the condition **degrades maintenance** of a demonstrated competency (e.g., depletion collapses
  applied Discernment).
Absent (i)–(iii), route to **Recognition/Context** (validate; no intervention). **Conditional interference**
(interferes for some presentations, not others — e.g., a negative self-appraisal that sometimes drives
foreclosure and sometimes is transient sting) is labelled *conditional* and requires an individual signal
before a barrier pathway is opened. This gate is the system's guard against over-pathologizing.

## 9. Competency / Barrier Pathway Logic (answers §VI, §VII)
Both pathways trace to canon. **Four-way determination retained — tested and justified** (it is the minimum
that separates "capacity missing" from "capacity blocked" from "both" from "leave it alone"; a 2-way model
loses the Neither exit and re-imports over-intervention). Simpler alternative rejected.

**Pathway A — Competency Strengthening.** *Problem Expression → Interference → Task → Competency →
Enhancement/Practice/Intervention → Developmental Application → improved Task functioning.* Governs when a
capacity needs to be developed, refined, or better applied.
- **Capability ladder (canonical Awareness→Practice→Application→Mastery) — do NOT equate any lower rung with
  the higher:** *knowing* (Awareness) → *understanding* → *demonstrating* (in practice) → *applying*
  (Developmental Application, in authentic context) → *maintaining* (across time/contexts). **Intervention
  completion ≠ competency development.** Measurement (§17) must locate the person on this ladder.

**Pathway B — Barrier Reduction.** *Problem Expression → Interference → Barrier (Internal/Relational/
Environmental) → competencies affected → barrier-reduction strategy and/or compensatory Enhancement →
restored competency expression → improved Application.*
- **Barrier reduction is an intervention *objective*, not a separate catalog.** A barrier may be addressed by
  psychoeducation, an existing Enhancement, competency practice (which can double as reduction),
  environmental or relational modification, targeted intervention, supported/professional intervention, or
  clinical treatment. **Do not assume every barrier needs a new intervention.**

**Four-way determination:**
| Class | Meaning | Route |
|---|---|---|
| **Competency-dominant** | Capacity under-developed/under-applied; no material blocker | Pathway A |
| **Barrier-dominant** | Capacity plausibly present but materially blocked | Pathway B |
| **Combined** | Both warranted | A + B (sequenced, §13) |
| **Neither / Recognition-Context** | Meaningful experience, no established interference | Recognition exit (no intervention) |

## 10. Change Target Architecture (answers §VIII)
A **Change Target** states *what must change for developmental functioning to improve* and **must trace to a
canonical construct** (a Competency and/or a Barrier). The descriptive target-types below are an **analytic
vocabulary, not permanent categories** — kept only because they aid mechanism selection:
competency-development · competency-application · barrier-reduction · behavioral · interpretive/cognitive ·
attentional · environmental · relational · recognition/education. **Rule:** a Change Target is invalid if it
cannot name (a) the Task it serves and (b) the Competency it builds *or* the Barrier it reduces. Targets
that name only a feeling ("feel more chosen") or an external outcome ("get selected") are rejected.

## 11. Change Mechanism Architecture (answers §IX — *tested for taxonomy bloat*)
**The distinction is necessary; a closed catalog is not.** Definition:

> **Change Mechanism** = the *active ingredient* — the specific process by which the Change Target is
> expected to change. A **Delivery Format** (worksheet, conversation guide, challenge, lesson, scenario,
> animation, reflection, interactive exercise) is the *vehicle*, not the mechanism.

**Requirement:** every future intervention must **name its mechanism** in open language and say **what the
user actually does** and **why that produces the target change**. The system does **not** impose a fixed
canonical mechanism taxonomy (that would re-create the very proliferation we're avoiding). Illustrative
mechanisms — *for description, not adoption*: evidence discrimination, cognitive differentiation, attention
redirection, behavioral rehearsal, graded exposure, response interruption, skills modeling, implementation
intentions, feedback/correction, environmental restructuring, repeated real-world application. Mechanisms
may be sourced from external science under §12. **This fixes the audit finding that the library confused
format (Conversation Guide/Worksheet/Challenge) with mechanism (it named formats and left mechanism `NOT
EXPLICITLY SPECIFIED`).**

## 12. External Intervention Science Standard (answers §X — standard only, no review yet)
> **Governing principle.** External intervention science may supply a *technique or mechanism*. **RLC owns
> the developmental target, the rationale, the timing, the relation to the Developmental Task, and the
> interpretation of change.**

- **May be adapted:** techniques/mechanisms with a plausible or evidenced pathway to an RLC Change Target
  (e.g., cognitive differentiation, graded exposure, implementation intentions) — *re-anchored* to a Task +
  Competency/Barrier + indication set.
- **Requires attribution:** any technique traceable to an external tradition (CBT, ACT, MI, exposure,
  emotion-regulation, implementation science, decision science, etc.) is **named and attributed**; not
  rebranded as original RLC.
- **Must not be rebranded:** an external technique used substantially unchanged is credited, never presented
  as an RLC invention.
- **RLC-specific adaptation =** external mechanism + RLC developmental target + phase/task anchoring +
  indication/contraindication set + RLC interpretation of what its change *means developmentally*. The
  adaptation (the anchoring), not the technique, is RLC's contribution.
- **Evidence documentation (per intervention):** source tradition; **evidence level = Theory-Derived vs
  Empirically-Supported vs Adapted-from-Evidenced**; strength/《citation TBD in the later review》; and
  whether RLC's *developmental* claim is theory-derived even when the technique is empirically supported
  (they are documented separately). *The current 333 are all Theory-Derived / In Development.*

## 13. Intervention Sequencing Logic (answers §XI — decision rules, not over-engineered)
Not always Barrier→Competency. Decision rules:
1. **Safety/clinical first.** If risk, danger, or clinical-tier need is present → refer / stabilize before
   any self-guided developmental work (§16).
2. **Environmental/relational barrier first** when it would nullify practice (e.g., an unsafe relationship
   makes "practice vulnerability" inappropriate — §15).
3. **Barrier-first (or concurrent)** when the barrier *prevents effective practice* (barrier-dominant).
4. **Competency-first as double-duty** when the competency practice *itself* reduces the barrier (e.g.,
   graded authentic-disclosure reduces rejection-fear while building Authenticity) — prefer this for
   efficiency when safe.
5. **Concurrent** when both are present, neither blocks the other, and load is tolerable.
6. **Recognition-only** when the Gate fails — no sequence; validate and stop.
Represent as a short triage tree; avoid per-case bespoke ordering.

## 14. Normal Emotion / Non-Pathologizing Standard (answers §XII)
> **Barrier presence ≠ emotion presence. Successful intervention ≠ emotional invulnerability.** A person may
> feel hurt, rejection, sadness, grief, loneliness, uncertainty, nervousness, disappointment, anger, or
> longing **while demonstrating healthy developmental functioning.**

**Operational test:** the target of change is the **interference**, never the emotion's existence. An
emotion/cognition is "resolved" when it may still be *present* but no longer meets the Interference Standard
(§8) — i.e., it no longer distorts evidence, blocks enactment, or degrades maintenance of the Task's
capacities. Measurement (§17) therefore assesses *interference*, not *presence*.

## 15. Safety & Context Standard (answers §XIII — governing standard only)
Every future intervention must be specifiable on: **indications · context conditions · contraindications ·
stop conditions · safety considerations · consumer suitability · professional/clinical dependency.**
Governing rule:

> **Context-Validity Rule.** An otherwise-relevant intervention must not be used when the context makes its
> mechanism inappropriate or unsafe. Three canonical failure modes to always check:
> (a) *sufficient contrary evidence already exists* — "gather more evidence" is wrong where danger is
> already established; (b) *unsafe/coercive relationship* — "practice vulnerability/authenticity" is
> contraindicated; (c) *accurate negative expectancy* — "challenge negative expectancy" must not invalidate
> an expectation supported by repeated observable behavior (it becomes evidence-affirming, not challenging).

## 16. Consumer / Clinical Boundary (answers §XIV)
The Playbook is a **self-guided educational/developmental product, not psychotherapy.** Propose a
**methodological Intervention-Intensity tool (not a new RLC construct, not a severity score on the Cluster):**
| Tier | Use when | Example condition |
|---|---|---|
| **T1 — Self-guided** | Low risk; no clinical assessment needed; low destabilization potential; educational/skill focus | evidence-reading practice; graded authentic disclosure in a safe context |
| **T2 — Facilitated / supported** | Benefits from coach/facilitator or Academy support; moderate complexity; feedback valuable | reorienting entrenched attention patterns; sustained barrier reduction |
| **T3 — Clinical-required** | Risk, safety concern, trauma processing, high destabilization potential, or need for professional judgment/assessment | persistent, severe self-worth barriers; suspected clinical condition; unsafe relationship |
Tiering is a function of **risk · impairment · assessment-need · trauma/processing · destabilization
potential · safety · complexity · required professional judgment** — assessed on the *intervention × context*,
**not** on the Cluster or a distress threshold. T3 targets are **referred, not delivered** by the Playbook.

## 17. Change Measurement Architecture (answers §XV)
Designed in from the start. For every future intervention, specify five indicator levels + keep five states
distinct (grounded in canonical Developmental Application + Awareness→Practice→Application→Mastery):
| Indicator | Question | Canonical anchor |
|---|---|---|
| **Target** | What should change? | Change Target (⑤) |
| **Mechanism** | How does the intervention produce it? | Change Mechanism (⑥) |
| **Proximal** | What changes during/immediately after practice? | Practice stage |
| **Application** | What can the person now *do* differently in a real relationship? | Developmental Application |
| **Developmental** | How does Task functioning improve? | Task Mastery / functioning |
| **Maintenance** | Does it persist/generalize? | Transition Readiness |

> **Five-state distinction (never conflate):** intervention **completion** ≠ **engagement** ≠ **skill
> demonstration** ≠ **Developmental Application** ≠ **developmental outcome.** The library currently can
> evidence, at best, completion — a measurement gap to close later.

## 18. Problem Resolution Standard (answers §XVI)
**Provisional principle endorsed as theoretically supported** (it is Task-Mastery + the non-pathologizing
standard, restated), with refinement:

> **An Experience Cluster problem is functionally improved when the experiences associated with it exert
> meaningfully less *interference* with the person's developmental functioning, AND the person demonstrates
> stronger *Developmental Application* of the capacities their current Developmental Task requires** — even
> if related emotions/thoughts remain present and regardless of any specific external relational outcome.

Explicitly **not** success: emotion elimination · thought elimination · never re-experiencing the problem ·
a desired external outcome · being selected · avoiding future conflict/rejection/loss. Resolution is
measured on §17's Application/Developmental/Maintenance indicators, not on affect presence or outcomes.

## 19. Maintenance & Generalization (answers §XVII)
Conceptualized via canonical Developmental Application (repeated demonstration across diverse situations,
adaptation to changing demands) + Transition Readiness:
- **Transfer** (outside the intervention) · **Breadth** (across multiple relational situations) ·
  **Robustness** (under emotional activation) · **Durability** (over time) · **Adaptivity** (to changing
  contexts) · **Recurrence-tolerance** (recurrence of the experience is *not* failure — the measure is
  whether interference and application have shifted, not whether the experience ever returns).
- **Prohibited:** streaks, gamification, points, arbitrary completion metrics (they measure engagement, not
  Application — and misrepresent recurrence as failure).

## 22. Relationship to the Existing Intervention Library (answers §XXI)
The Change System sits **above** the library; the 333 templates are **not** replaced here. The architecture
makes each future intervention answerable to a fixed interrogation (the seed of the later **Intervention
Development Standard** — *not* written here beyond this boundary):
> problem/function warranting it · RLC construct targeted · mechanism · **active ingredient** · what the user
> actually does · proximal change · developmental change · indications · contraindications · evidence
