## Part B — Per-cluster ruling template (repeat once per cluster, before derivation)

For each cluster the owner rules:
1. **Phase confirmation** — is the cluster's interference in the stage it's filed under? (Phase → Task →
   Competency is the whole derivation chain, so this is foundational, not cosmetic.)
2. **Canonical partition questions** — scaffolding rows to exclude; any mis-mapped statement blocks to
   keep-or-redistribute (source canon changes only by owner ruling, never by the pipeline).
3. **Coverage / FCQ dispositions** — for each non-behavioural major problem expression, is the required
   capacity covered by a competency, routed via a Task-Supporting target (FCQ), or recorded as a known limit?
4. **Grade + claim scope** — assign the disposition (Sufficient / with-Recognition / Partially / Insufficient)
   and bound the product claim (aids, not guarantees).
5. **Shared-tool boundaries** — where a Core Play or competency is shared with another cluster, set a
   distinct `playId` + re-derived fidelity names *before* authoring, so two Playbooks don't ship the same tool.
