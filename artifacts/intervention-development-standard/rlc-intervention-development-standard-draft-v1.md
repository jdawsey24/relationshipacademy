# Relationship Life Cycle™ Intervention Development Standard — Draft v1

**Status:** DRAFT v1 for human review. **Methodological/operational standard — NOT an intervention-generation
task.** No Cluster 1 interventions created; the 333 existing records are untouched; no Playbook redesign; no
literature review; no framework/competency/barrier modification. Governing architecture: **RLC Change System
Architecture — Final v1 (rev v1.1)** (`../change-system/rlc-change-system-architecture-final-v1.md`). This
Standard defines *how valid RLC interventions will be identified, selected, adapted, designed, evidence-
sourced, developmentally anchored, safety-bounded, delivered, practiced, measured, reviewed, validated, and
translated across consumer/professional contexts* — rigorously enough that another developer could apply it
to any Experience Cluster while preserving RLC theoretical integrity.

**Product-independence principle (governing):** the Standard is **not** optimized for the $29 consumer
Playbook. It must serve consumer Playbooks, Academy, professional education, clinician tools, workshops,
certification, research, and future applications. **The product later selects the subset of interventions
appropriate for its delivery context; the methodology comes first.**

# DELIVERABLE 1 — Intervention Development Standard (the standard itself)

## 1.1 What counts as an RLC Intervention (definition)
> **An RLC Intervention is an intentional, specified change process that acts on a defined Change Target,
> through a stated Change Mechanism, in service of improved Developmental Application of the competencies a
> person's current Developmental Task requires — with specified user action, expected proximal change,
> indications/contraindications, and a way to observe whether it is working.**

**Necessary conditions (all must hold) — a candidate is *not* an RLC Intervention unless it can state:**
1. a **Change Target** traced to the Developmental Task + a canonical **Competency and/or a Canonical Barrier
   category** (§Change System §8);
2. a **Change Mechanism** — the active process expected to move that target (not a format);
3. the **user action** — what the person concretely does;
4. an **expected proximal change** — an observable/reportable sign the mechanism may be functioning;
5. a **developmental rationale** — why moving this target should improve Developmental Application;
6. **indications + contraindications + stop/referral conditions**;
7. an **evidence label** (§Deliverable 2/ §1.4) and, where external, **attribution**.

**An RLC Intervention is therefore distinct from** (each of these may *appear inside* a Play or an
intervention, but is not, by itself, an intervention):
| Not an intervention (by itself) | Why |
|---|---|
| education / information / psychoeducation | conveys knowledge; no change process on a target — **unless** correcting a knowledge deficit is itself the mechanism (§1.5, Del. 6 rule) |
| recognition / validation / normalization | supports without acting on a Change Target (Change System "Recognition/Context") |
| reflection / journaling / discussion / activity | a delivery format or engagement act; mechanism unspecified |
| worksheet / conversation guide / challenge / lesson / video / scenario / animation | **delivery formats**, not mechanisms |
| a behavioral suggestion | a target without a specified mechanism, dose, feedback, or transfer |
| a Developmental **Practice** / **Enhancement** | reinforces/strengthens an already-identified capacity; may be a *component* of an intervention (§Deliverable, Practice-vs-Intervention) |
| a clinical treatment technique | out of RLC self-guided scope unless adapted + suitability-gated |
| a **Play** / Playbook module | the consumer-facing package that *contains* intervention(s) (§Del. 1.9) |

**Rule:** *Not every worksheet, exercise, challenge, or prompt qualifies.* A thing qualifies only when it
satisfies §1.1's necessary conditions.

## 1.2 The Intervention Evidence Chain (mandatory; every intervention must complete it)
```
Presenting Experience / Problem Expression
  → Functional Interference (established | conditional; evidence stated)
  → Developmental Context (Phase → Task)
  → Change Target (traced)
  → Relevant Competency and/or Canonical Barrier category
  → Change Mechanism (active process)
  → Intervention Technique (+ source & evidence label)
  → User Action
  → Expected Proximal Change
  → Developmental Application (authentic-context enactment)
  → Expected Developmental Outcome
  → Maintenance / Generalization
```
**Evidence required at each link (no link may be asserted "because it sounds helpful"):**
| Link | Required evidence |
|---|---|
| Functional Interference | Passes the Change System Gate: evidence the condition interferes with acquisition/application/integration/maintenance of a Task competency. *Hypothesis-level from statements is allowed only to open analysis; barrier/mechanism claims need more (Statement Evidence Rule).* |
| Developmental Context | Canonical Phase→Task (`fw_phases`). |
| Change Target | Traceable to Task + a canonical Competency and/or Barrier category. |
| Competency / Barrier | Canonical `kb_competencies` profile / one of the three barrier categories (never a bespoke barrier). |
| Change Mechanism | An articulated active process + why it moves *this* target. |
| Technique | A named technique (external-attributed or existing-RLC or theory-derived) that instantiates the mechanism. |
| Proximal change | A stated observable/reportable indicator. |
| Developmental Application | Mapped to Behavioral Indicators (BI) for the competency. |
| Outcome / Maintenance | Reduced interference + stronger Application (Del. 6 success standard); generalization plan. |

> **The one question the chain must answer:** *Why should doing THIS produce change in THIS target for THIS
> developmental purpose?* No admission without an explicit answer.

## 1.3 Change-Mechanism requirement (no closed taxonomy)
Per Change System §9, **no closed RLC mechanism taxonomy is created.** Instead, every intervention must
specify, in open language: **(1) what the user actually does; (2) the psychological/behavioral/relational/
attentional/environmental/learning process expected to occur; (3) the Change Target it affects; (4) why that
change should improve Developmental Application; (5) the observable proximal change that would indicate the
mechanism may be functioning.** Enforced distinctions (each must be separately stated):
**mechanism ≠ technique ≠ delivery format ≠ content ≠ outcome.**
- "worksheet" is a **format**, never a mechanism. "Practice authenticity" is **not** a sufficiently specified
  intervention (no mechanism, dose, proximal change, transfer, or feedback). The Standard **forces
  specificity** by rejecting any record that leaves mechanism = format or leaves fields 2–5 blank.

## 1.4 Evidence-strength labels (smallest sufficient set)
Every intervention carries **exactly one External-technique label** and **one RLC-application label** (kept
separate — an evidenced technique does not make the RLC application validated):
| External technique label | Meaning |
|---|---|
| **Empirically-Supported** | the technique/mechanism has empirical support in its source literature |
| **Evidence-Informed** | consistent with evidence but adapted/extrapolated beyond the tested case |
| **Not-Externally-Sourced** | no external technique claimed (theory-derived or existing-RLC) |
| RLC-application label | Meaning |
|---|---|
| **RLC-Theory-Derived** | coherent with RLC theory; not yet tested within RLC |
| **RLC-Pilot-Tested** | usability/pilot data within RLC exists |
| **RLC-Empirically-Supported** | validated within RLC (none currently) |
> For any intervention one must be able to answer: *what exactly is supported by evidence?* and *what remains
> theoretical/untested?* The current 333 would all be **Not-Externally-Sourced / RLC-Theory-Derived**.

## 1.5 Recognition/Context vs Intervention (accurate labeling)
Recognition/Context content (normalization, validation, psychoeducation, literature, "you may recognize…",
conceptual reframes that are not themselves a change technique) **is allowed and may be essential**, but must
be **labeled Recognition/Context, not Intervention.** *Do not inflate education into intervention.*
**Exception (education-as-mechanism):** when a **knowledge deficit is the interference** and correcting it is
*necessary for Developmental Application* (e.g., the person does not know what reciprocal behavior looks
like), the educational correction **is** the mechanism — and must then satisfy all §1.1 conditions (target,
proximal change, transfer, feedback), not merely inform.

## 1.6 Interpretive/cognitive targets without medicalizing (Change System-faithful)
Because most Experience Cluster statements are thoughts/interpretations/emotions/experiences, the Standard
**supports interventions targeting interpretation, attention, evidence discrimination, expectancy, decision
processes, self-evaluation (where developmentally relevant), behavioral/relational response, and
environmental conditions** — **without assuming pathology.** Constraints:
- **No silent creation of new competencies or barriers.** Every such intervention must still trace
  Functional Interference → existing Task → Competency/Application (and, if a barrier, a **canonical
  category**, per the v1.1 Observed-Pattern-vs-Canonical-Barrier rule).
- If a required Change Target **genuinely exceeds** the canonical architecture, **raise a Framework Coverage
  Question** (human adjudication, Del. 8) — **do not invent a construct.**

## 1.7 Dosage standard (mechanism-derived, no arbitrary prescriptions)
Dosage (one-time vs repeated; frequency; duration; spacing; progression; rehearsal; real-world use; return-
and-review; maintenance) **derives from mechanism + learning requirement + target + complexity + context +
evidence** — **never** a manufactured "do this for 30 days." The governing question: *how much practice is
enough to reasonably expect learning or behavioral transfer for this mechanism?* Where evidence is
unavailable, dosage is **labeled Provisional** with its rationale. Insight-type mechanisms (e.g., cognitive
differentiation) may need few, well-designed exposures; skill-acquisition mechanisms (e.g., behavioral
rehearsal) typically need distributed practice + real-world application.

## 1.8 Feedback & corrective-learning standard
Every intervention must let the user determine: **did I understand it · did I perform it as intended · what
happened · what does the result mean · repeat / modify / discontinue / escalate · did the intended proximal
change occur.** Feedback must be **corrective-learning oriented**, tied to the proximal-change indicator and
the competency's Behavioral Indicators. **Prohibited:** right/wrong scoring where nuance is required,
gamification, streaks, arbitrary percentages, relationship-outcome scoring. For interpretive/ambiguous
targets, feedback is **reflective discrimination** ("does what you observed fit a fact or an interpretation?"),
not a correctness verdict.

## 1.9 Intervention vs Play (methodological, no Playbook redesign)
> **Intervention ≠ Play.** A **Play** is the consumer-facing package of one or more valid intervention
> components. A Play may combine concise education + recognition + an intervention + rehearsal + behavioral
> experiment + real-world application + return-and-review + maintenance cue — **but the underlying
> intervention (target, mechanism, evidence label) must remain identifiable inside the Play.** One Playbook
> may contain **multiple Plays** because one Experience Cluster may contain multiple Problem Expressions and
> Change Targets. Statements do **not** become Plays; the pipeline is Statements → Problem Expressions →
> Interference Analysis → Change Targets → Change Mechanisms → Interventions → (packaged as) Plays.

## 1.10 Practice vs Intervention vs Enhancement (no duplication of Enhancement architecture)
| Construct | Role | Sufficient alone when… |
|---|---|---|
| **Developmental Enhancement** (canonical) | strengthens an already-identified capacity | the capacity exists and only needs reinforcement (Competency-dominant, no material interference) |
| **Developmental Practice** (canonical) | repeated implementation of an Enhancement | maintenance/repetition is the need |
| **RLC Intervention** | intentionally alters a specific Change Target via a specified mechanism | interference is present and a targeted change (not mere reinforcement) is required |
Rules: an Enhancement **can serve as a component** of an intervention; an intervention **usually requires
practice afterward** for transfer; **practice alone is inadequate** when interference blocks the capacity
(barrier-dominant / combined). Do not re-catalog Enhancements as interventions.

## 1.11 Real-world application standard (bridge to Developmental Application)
Every change-producing intervention must specify how learning **transfers into authentic relational
situations.** Underlying standard (not all six must be user-facing steps): **Learn/Understand → Rehearse →
Apply → Observe → Adjust → Generalize.** The central test: *can the user apply the relevant capacity when the
actual relational situation occurs?* Interventions that end at "understand" without a transfer path do not
meet the Developmental Application bridge.

## 1.12 Cultural & contextual validity requirements
Interventions must **not** define healthy functioning as one communication style, gender-role arrangement,
relationship structure, level of emotional expressiveness, sexual norm, timeline, degree of independence/
interdependence, or dating convention. Developmental functioning stays anchored to the **competency
definition and relational context**, not a cultural preference. Each intervention record must document:
**contextual/cultural assumptions made · the range of contexts in which the mechanism holds · adaptations
needed for different relationship structures/norms · any content that presumes a specific convention** (flag
for review).

## 1.13 Success / Mastery standard (no promise of external outcomes)
Success is **never** defined as: never feeling the feeling again · the thought disappearing · dating becoming
easy · the relationship surviving · finding a partner · another person changing · conflict disappearing.
> **Successful intervention (frozen from Change System §17):** the associated experiences exert **meaningfully
> less functional interference** AND the person demonstrates **stronger Developmental Application** of the
> Task's capacities — expressed as: increased capacity, better evidence discrimination, increased behavioral
> flexibility, appropriate decision-making, maintenance/generalization, and **recurrence tolerance** (a
> recurrence is not failure). We may claim: *if the person learns and consistently applies these
> interventions, [these capacities] should be stronger and [this interference] reduced* — **never** an
> external relational outcome.

## 1.14 Versioning / validation lifecycle
**Intervention lifecycle (adopt; distinguishes coherence from evidence from validation):**
`Proposed → Theory-Reviewed → Evidence-Reviewed → Usability/Pilot-Ready → Pilot-Tested → Revised →
Validation-Candidate → RLC-Empirically-Supported`. Each intervention carries its **stage** + the separate
evidence labels (§1.4). The current 333 sit at **Proposed/Theory-Derived** at best. **No intervention may be
presented to consumers above its validated stage** (e.g., theory-derived ≠ "proven").

## 1.15 Human-review requirements (no automated theory creation)
**Mandatory human adjudication** before admission for: novel Change Targets · weak or ambiguous competency
mappings · novel mechanisms · adaptations of clinical techniques · safety-sensitive interventions ·
professional/clinical routing · **Framework Coverage Questions** · weak-evidence interventions ·
interventions targeting psychologically complex processes (e.g., self-evaluation) · culturally sensitive
assumptions. **An automated pipeline may draft and self-check, but may never silently (a) create a competency
or barrier, (b) raise the validated stage, or (c) resolve a Framework Coverage Question.**

# DELIVERABLE 2 — Intervention Evidence Hierarchy (borrow → adapt → refine → invent)
Favors evidence and parsimony over invention; **new creation is the last option, not the default.**
| Level | Source | Use when | Evidence label starts at |
|---|---|---|---|
| **L1 — Adopt existing empirically-supported technique** | external evidence base | an established technique already fits the required Change Target/mechanism, usable with attribution + minimal change | External: Empirically-Supported · RLC-app: Theory-Derived |
| **L2 — Evidence-informed adaptation** | external technique, re-anchored | an established technique can be responsibly adapted to the RLC target/context | External: Evidence-Informed · RLC-app: Theory-Derived |
| **L3 — Refine an existing RLC asset for specificity** | the 333 templates / Enhancements | an existing RLC structure is sound but competency-general and needs target-specific content | External: as-inherited · RLC-app: Theory-Derived |
| **L4 — Theory-derived new RLC intervention** | RLC theory | **no** sufficiently-fitting external or existing asset exists | External: Not-Externally-Sourced · RLC-app: Theory-Derived |
**Selection rule:** *technique fits the Change Target — never pick a modality first and force the problem into
it.* Ascend to L4 only after documenting why L1–L3 fail. The decision (`borrow/adapt/refine/invent`) is
recorded with rationale.

# DELIVERABLE 3 — Consumer / Professional Suitability Standard (resolves Change System §14 HELD)
**Verdict: a tiered structure IS defensible, but only if each tier is driven by observable/reportable
routing information — not by mild/moderate/severe.** Adopt **four routing outcomes** (T1/T2/T3 + Excluded),
each decided by *routing factors*, and require an **individual routing signal source** (the item the
Snapshot currently lacks — see Del. 8).

**Routing factors (assessed on the *intervention × context*, not the Cluster):** technique complexity ·
likelihood of misapplication · emotional-activation potential · relational safety / coercion-abuse concerns ·
clinical dependency · need for individualized formulation · potential to worsen risk · need for real-time
feedback · cognitive load · user ability to self-correct · contraindications · ambiguity in interpreting the
result.

| Routing outcome | Assigned when… | Example condition |
|---|---|---|
| **R1 — Self-guided** | low misapplication risk, low activation, self-correctable, unambiguous result, no safety dependency | evidence-observation practice in a safe context |
| **R2 — Self-guided with optional support** | benefits from facilitation/feedback; moderate ambiguity or cognitive load; still low risk | reorienting entrenched attention; sustained interpretive change |
| **R3 — Facilitated / professional** | needs individualized formulation, real-time feedback, or professional judgment; higher activation | working an entrenched self-evaluation pattern |
| **Excluded (clinician-dependent / refer)** | risk, safety concern, trauma processing, high destabilization potential, or clinical assessment required | severe/persistent self-worth barrier; suspected clinical condition; unsafe/coercive relationship |
> **Routing requires an individual signal** (severity/impairment/safety) that the Snapshot (experience, not
> impairment) does not currently supply. **Del. 8 escalates this as the top blocking decision.** Until
> resolved, **default routing is conservative** (education/recognition or R1-only) and safety-screen gating
> at point of delivery. The tier names are provisional pending that signal.

# DELIVERABLE 4 — Intervention Quality Rubric (QA gate)
Each dimension rated **Strong / Adequate / Weak / Absent / N-A**. **Disposition** is a function of the
profile, not an average.
| # | Dimension | A passing intervention shows… |
|---|---|---|
| 1 | Theoretical traceability | complete Evidence Chain to canonical constructs |
| 2 | Change-Target specificity | one clearly-stated, construct-traced target |
| 3 | Mechanism clarity | mechanism ≠ format; fields §1.3(1–5) present |
| 4 | Evidence support | correct dual labels; attribution where external |
| 5 | Developmental alignment | serves the Phase/Task; BI-mapped |
| 6 | Actionability | concrete user action |
| 7 | Practice/repetition quality | mechanism-derived dose (not arbitrary) |
| 8 | Real-world transfer | explicit Application/transfer path |
| 9 | Feedback quality | corrective-learning, non-gamified |
| 10 | Measurement readiness | proximal + Application indicators specified |
| 11 | Context validity | indications/contraindications/stop/referral |
| 12 | Safety | Context-Validity Rule checks pass |
| 13 | Consumer suitability | routing outcome assigned with factors |
| 14 | Cultural/contextual flexibility | assumptions documented; not one-norm |
| 15 | Parsimony | no unnecessary construct/complexity |
| 16 | Non-duplication | not a rename of an existing intervention (Del. 6 rules) |
| 17 | Generalization/maintenance | maintenance + generalization target |

**Dispositions:** **Admit** · **Admit-with-Adaptation** · **Professional-Only** (route R3/Excluded) ·
**Hold-for-Evidence** (mechanism sound, evidence/label insufficient) · **Reject** (fails 1–3, or is a format/
recognition mislabeled as intervention, or requires an uncanonical construct without a Framework Coverage
Question). **Any Weak on 1, 2, 3, or 12 blocks Admit.**

- **A · PE-1 without inventing a self-worth competency.** ✅ The Standard determines: warrants intervention
  *only conditionally* (Gate); interference = the self-verdict foreclosing Objectivity/Reflection; destination
  = **existing** competencies (Objectivity/Reflection/Authenticity) with an **Internal barrier category**
  candidate; external science (cognitive differentiation, L2) likely needed; self-guided **only** below a
  severity threshold that **requires an individual signal we lack**; success = reduced interference + stronger
  Objectivity/Reflection Application, **not** feeling chosen. **No self-worth competency invented.** Residual:
  the severity signal (Del. 8).
- **B · PE-4 Reciprocity without scorekeeping.** ✅ Change Target = *pace investment to observed reciprocity*;
  mechanism = response-interruption + reciprocity **discrimination**; **guardrail enforced** (information, not

- **C · PE-6 distorted vs accurate expectancy.** ✅ The Gate + Context-Validity Rule §13c **prohibit

  pre-discounting only. **Requires an individual distorted-vs-accurate signal** (flagged). The Standard will
  not train someone to override accurate perception.
- **D · PE-8 loneliness.** ✅ **Recognition/Context only. No intervention.** The Standard does not manufacture
  an intervention because a feeling is unwanted — non-pathologizing test **passed**.
