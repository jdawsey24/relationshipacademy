# Cross-Cluster Behavioral Evidence Rule — DRAFT v1 (for approval)

**Status:** **Provisionally Validated — Cluster 1 Prototype** (owner-approved for prototype use). NOT globally validated; NOT operationalized across other clusters. Global validation requires successful application to additional clusters with different phenomenological/developmental profiles.
Do not apply to other clusters until approved.

## Purpose
Experience Cluster assignment tells us *what relational experience a statement represents* — it does
**not** define the complete behavioral repertoire relevant to navigating or changing that experience.
So requiring every behavioral Play to originate from a Self-Behavior statement canonically assigned to
the **same** Experience Cluster is unnecessarily restrictive. This rule permits **governed** use of
Self-Behavior evidence from *other* clusters, under a strict evidentiary standard — never automatic
"borrowing."

## Evidence hierarchy (a candidate's tier is part of its record)
- **Tier 1 — Direct Behavioral Evidence.** Self-Behavior from the SAME Experience Cluster with clear developmental relevance. (Highest.)
- **Tier 2 — Governed Cross-Cluster Behavioral Evidence.** Self-Behavior from ANOTHER cluster that satisfies the complete evidence chain below. **Requires human approval** (first implementation — every Tier 2 case).
- **Tier 3 — Task-Supported Behavioral Derivation.** A behavioral application strongly supported by the RLC task/competency architecture but with no direct behavioral statement. Lower evidence status; **explicit human approval**.
- **There is NO Tier 4.** Generic relationship advice is never admissible.

Cross-cluster evidence is **secondary** to direct evidence: use it only where direct evidence is
**Limited or Insufficient** AND the candidate **materially improves actionability** AND the full chain
is satisfied. A Playbook with sufficient direct evidence does not get padded with borrowed behaviors.

## Mandatory evidence chain (all links required; developmental + behavioral, not semantic)
```
Target-cluster phenomenology
  → relevant RLC Phase
  → relevant Developmental Task
  → relevant RLC competency (or a clearly task-supported behavioral requirement)
  → candidate Self-Behavior (from its canonical cluster)
  → behavioral relevance: would changing / increasing / decreasing / observing / clarifying /
    preserving / replacing this behavior MATERIALLY improve the person's ability to perform the
    target cluster's developmental task?
```
If the answer to the last link is not clearly yes → **exclude**.

## Rules
1. **Canonical mappings never change.** A borrowed statement stays canonically assigned to its original cluster. Cross-cluster use is an **application relationship**, not a remapping.
2. **Phenomenological similarity alone is insufficient.** Emotional resemblance between clusters is not evidence. The chain must be developmental and behavioral.
3. **No inferred psychological mechanism.** No bridge like *feeling unchosen → abandonment fear → chasing → stop chasing*. No attachment style, unconscious motive, personality trait, pathology, or generic psychology unless directly established by approved source material.
4. **Cross-cluster evidence does not establish prevalence.** Never say/imply "people with this result do this." The application must be **conditional**: ✔ "If you notice yourself increasing your effort when the other person becomes less available…" — ✗ NOT "When you start chasing because you're afraid they won't choose you…". The behavior is an *applicable intervention pathway*, not an attributed trait.
5. **Same-phase evidence is preferred.** Cross-**phase** candidates need stronger justification and human review (the task/context is less likely to align).
6. **Existing competencies take priority.** A candidate that operationalizes an existing competency for the target phase/task is stronger. Do NOT invent competencies. Task-supported/competency-gap candidates are admissible only at a **lower evidence status** with human review.
7. **The behavior must matter to the target task.** Not "could this help?" but "would altering this behavior *materially* improve performance of THIS cluster's developmental task?" If not, exclude.
8. **Cross-cluster is secondary** to direct evidence (see hierarchy).
9. **Fill a meaningful gap only.** Use cross-cluster evidence when direct evidence is limited/insufficient AND it materially improves actionability AND the chain holds — not to enlarge Playbooks.
10. **Negative findings are valid.** The rule must be able to return **`No admissible cross-cluster behavioral evidence`**. Do not weaken the standard to rescue every cluster (e.g., content-specific clusters like physical intimacy, finances, parenting, inherited patterns).
11. **Human confirmation.** For the first implementation, EVERY Tier 2 application requires human approval before becoming an approved Core Play application. Whether classes of Tier 2 can later be approved algorithmically is a future decision after enough adjudicated cases.
12. **Prototype before scale.** Apply only to Cluster 1 first; evaluate each candidate independently against this rule.

## Required output per candidate (application evaluation)
candidate behavior · canonical source cluster · evidence tier · complete evidence chain · relevant
competency · relationship to the developmental task · proposed behavioral target · duplicates an
existing target-cluster Play? · context limitations · what we MAY legitimately say to the consumer
(conditional) · what we may NOT infer/say (prevalence/mechanism) · confidence · recommendation
(**Admit / Reject / Human Review**). Under Rule 11, every admissible Tier 2 candidate resolves to
**Human Review** in this first pass — never auto-Admit.
